SECTION 2: LIKELY QUESTIONS
════════════════════════════════════════════

Q: What is your Macro F1 score?
A: Check src/project_summary.json
   and src/model_metadata.json

Q: Why LightGBM over Random Forest?
A: LightGBM is faster, handles imbalance
   better with class_weight='balanced',
   supports early stopping, and gives
   better performance on tabular data
   with gradient boosting.

Q: How did you handle class imbalance?
A: Two ways:
   1. class_weight='balanced' in LightGBM
   2. SMOTE applied ONLY inside training
      folds during cross-validation to
      prevent data leakage.

Q: What is data leakage?
A: When test data information contaminates
   training. If SMOTE is done before CV
   split, synthetic samples based on test
   data appear in training — giving
   falsely optimistic scores.

Q: What did the ablation study prove?
A: That external context features
   (weather + factory load) significantly
   improve Macro F1 score over IoT-only
   baseline. Confirmed by paired t-test
   (p<0.05) and Wilcoxon test.

Q: What is threshold tuning?
A: By default models use 0.5 threshold.
   For imbalanced failure prediction,
   lowering the threshold catches more
   failures (reduces miss rate) at cost
   of more false alarms. We found the
   balanced optimal threshold.

Q: What noise types did you test?
A: 5 types:
   1. Gaussian — random measurement error
   2. Missing — sensor connection loss
   3. Drift — gradual sensor degradation
   4. Spike — electrical interference
   5. Scaling — calibration errors
